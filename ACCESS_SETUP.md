# Защита доступа к CSCA Mathematics

Проект остаётся React + Vite. Учебные материалы, дизайн и локальное сохранение прогресса не заменены. Вход и админка работают на сервере отдельно от приложения курса.

## Что защищено

- `/` и все страницы курса требуют пользовательскую или администраторскую сессию.
- Прямые ссылки на уроки, доску и JavaScript-файлы с материалами также защищены.
- `/admin/login` — отдельный вход администратора. `/admin` и операции изменения пароля требуют именно администраторскую сессию.
- Пользовательский пароль — строка из шести цифр, в том числе с ведущими нулями. В Neon хранится только scrypt-хеш с индивидуальной солью.
- Сессии — случайные непрозрачные токены в HTTP-only cookie; в базе хранятся только хеши токенов. Пользовательская сессия действует 7 дней, администраторская — 8 часов.
- В production cookie имеет `Secure`, `HttpOnly`, `SameSite=Lax`, `Path=/` и префикс `__Host-`. Пароли и сессии не сохраняются в localStorage.
- Смена пароля сразу делает старый пароль и старые пользовательские сессии недействительными. Уже открытая вкладка проверяет доступ при переходе, возвращении на вкладку и каждые 30 секунд.
- Ограничение попыток входа: 12 для пользователя, 6 для администратора за 15 минут на IP. Изменяющие запросы требуют тот же Origin для защиты от CSRF.
- Если база недоступна, сервер не открывает курс без проверки.

## Переменные окружения

Нужны ровно три серверные переменные:

```dotenv
DATABASE_URL=
ADMIN_USERNAME=
ADMIN_PASSWORD=
```

`DATABASE_URL` — строка подключения к уже существующей базе Neon. `ADMIN_USERNAME` и `ADMIN_PASSWORD` — данные входа в админку. Пароль администратора тоже храните строкой: ведущий ноль является частью пароля.

Локальный `.env.local` уже заполнен предоставленными владельцем значениями и исключён из Git. Реальных значений в `.env.example` и этой инструкции нет. На другой машине скопируйте `.env.example` в `.env.local` и заполните его самостоятельно.

После изменения `.env.local` остановите и заново запустите локальный dev-сервер.

Не добавляйте префикс `VITE_` к секретам: такие переменные Vite предназначены для браузера. Не публикуйте `.env.local`, URL базы, пароли или дампы базы.

## Локальный запуск

Используйте Node.js 22.12+ или совместимую более новую версию.

```powershell
npm install
npm run dev
```

Откройте адрес, который Vite напечатает в терминале. Обычно это `http://localhost:5173`, но занятый порт может измениться.

1. Главная страница и любой урок без входа должны отправлять на `/login`.
2. Откройте `/admin/login` на том же адресе и введите данные из `.env.local`.
3. В `/admin` нажмите «Сгенерировать новый пароль», затем «Скопировать».
4. Новый пароль показывается только в момент генерации. Сохраните его и передайте ученикам. После перезагрузки его нельзя восстановить из хеша; при потере сгенерируйте следующий.
5. В отдельном приватном окне откройте главную страницу и войдите с новым паролем.
6. Проверьте неверный пароль, запрет `/admin` для ученика и смену пароля. После смены старый пароль и старая пользовательская сессия не должны работать.

После выполненных интеграционных проверок в базе установлен случайный пароль, который не выводился в терминал. Перед выдачей доступа ученикам сгенерируйте собственный новый пароль через админку.

Сборка:

```powershell
npm run build
```

Автоматический интеграционный тест (по желанию):

```powershell
npm run check:access -- --url=http://localhost:5173 --rotate-password
```

Передайте фактический адрес запущенного dev-сервера. ВАЖНО: тест работает с базой из `.env.local`, действительно меняет пароль и отзывает пользовательские сессии. Не запускайте его на общей рабочей базе во время занятий. Он проверяет входы, разграничение ролей, Neon, ведущие нули, отзыв старого пароля/сессий, CSRF, ограничение параллельных попыток, отсутствие секретов в Git и в `dist`. В конце временный тестовый пароль заменяется новым случайным. Затем снова сгенерируйте пароль в админке.

## Neon

Новая база не создаётся. При первом обращении сервер автоматически создаёт в указанной базе:

- `site_settings` — единственный действующий хеш пароля, версия и время изменения;
- `site_auth_sessions` — хеши токенов, роли, срок действия и версия пароля;
- `site_login_limits` — счётчики попыток входа без сохранения IP в открытом виде.

При первом запуске на совершенно пустой базе пользовательского пароля ещё нет, поэтому доступ закрыт до первой генерации в админке. Прочие таблицы не удаляются.

## Vercel: перед push

1. В проекте Vercel откройте **Settings → Environment Variables** и добавьте `DATABASE_URL`, `ADMIN_USERNAME`, `ADMIN_PASSWORD` с реальными значениями. Укажите нужные окружения: как минимум Production, а для защищённых preview-развёртываний также Preview.
2. Убедитесь, что проект деплоится из полного репозитория, а не только из папки `dist`. Защита требует `middleware.js` и функции `api/access.js` вместе со статическими файлами.
3. Конфигурация уже указывает Vite, `npm run build` и `dist`. Vercel Routing Middleware проверяет запросы до выдачи страниц и ресурсов; API использует Node.js и серверный драйвер Neon.
4. Используйте поддерживаемую Vercel версию Node.js, например 22.x.
5. Проверьте секреты до коммита:

```powershell
git check-ignore .env.local
git status --short
git diff
```

Первый вызов должен вывести `.env.local`; файл не должен появляться в списке изменений для коммита. Не используйте `git add -f` для env-файлов. Проверьте также GitHub: репозиторий с закрытым учебным материалом должен быть private, доступ к нему и к Vercel — только у доверенных людей.

Дальнейшие команды выполняет владелец:

```powershell
git add .
git diff --cached --stat
git commit -m "Add password protection"
git push
```

После деплоя повторите проверки главной страницы, прямого URL урока, `/admin/login`, генерации, входа и отзыва старого доступа на адресе Vercel. Новый деплой здесь не выполнялся: действующий опубликованный сайт получит защиту только после успешного развёртывания этих изменений с переменными окружения. Изменение переменных в Vercel требует нового деплоя.

Документация платформы: [Vercel Routing Middleware](https://vercel.com/docs/routing-middleware), [API middleware](https://vercel.com/docs/routing-middleware/api).

## Границы защиты

Это защита от неавторизованных посетителей, а не DRM. Человек, которому вы дали пароль, всё равно сможет прочитать и скопировать доступный ему материал. Удалённо стереть уже скачанную копию невозможно. Общий пароль можно передать другому человеку; для индивидуального отзыва нужны отдельные учётные записи, которые в этом изменении не добавляются.

Строка подключения к Neon была передана в переписке. Перед production рекомендуется заменить пароль роли базы в Neon и обновить `DATABASE_URL` в `.env.local` и Vercel. Самостоятельно серверные секреты и настройки аккаунтов здесь не менялись.

`npm audit` обнаружил два существовавших low-предупреждения для KaTeX/react-katex. Они не относятся к новым зависимостям авторизации; принудительное несовместимое обновление математического рендерера не выполнялось.

## Исправление диагностики входа на Vercel

В опубликованной версии воспроизведён ответ 503 при входе. Это подтверждает серверный сбой, а не неверно введённый пароль. Точная причина той версии не установлена: её обработчик скрывал все исключения одним сообщением и не записывал безопасную диагностику.

В локальном исправлении:

- Настройки читаются через серверный `server/config.js`. Обрабатываются внешние пробелы, кавычки и случайно вставленная строка вида `DATABASE_URL='…'`. Ведущие нули пароля сохраняются.
- При отсутствующих настройках, неверном формате подключения, отказе Neon в доступе и ошибках сети возвращаются разные безопасные сообщения.
- Ошибки записываются в журнал с маркером `csca_access_failure`, этапом и `requestId`. Пароли, URL подключения, cookies, токены и исходный текст ошибки драйвера не записываются.
- Инициализированная база не выполняет `CREATE TABLE` и `CREATE INDEX` на каждом холодном старте Vercel.
- Проверка сессий остаётся серверной: при любой ошибке доступ не открывается.

Созданы `server/config.js`, `server/access-errors.js`, `scripts/check-access-config.test.mjs`. Обновлены `server/database.js`, `server/auth.js`, `server/access-api.js`, `server/protect.js`, `public/auth/access.js`, `package.json` и эта инструкция. Новых зависимостей нет; учебные материалы и дизайн не изменены.

Проверка этого исправления без изменения пароля базы или учеников:

```powershell

npm run build
```

Семь регрессионных тестов и production-сборка прошли. Дополнительно проверены реальная Neon, вход с кавычками/префиксом в настройках, защищённая production-cookie, доступ к `/admin`, закрытие сессии и сохранение текущей версии пользовательского пароля. Тестовые админ-сессии удалены; пароль учеников не менялся.

После push дождитесь нового успешного деплоя. Если вход всё ещё не проходит, новая страница покажет конкретное сообщение и короткий код обращения. По этому коду в Vercel Logs можно найти запись `csca_access_failure` и увидеть этап сбоя. Наличие локального исправления не подтверждает исправление живого деплоя до его публикации и проверки.
